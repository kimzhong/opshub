## 1. 环境准备

### 1.1 硬件要求

| 资源 | 最低 | 推荐 |
|---|---|---|
| CPU | 8 cores | 16 cores |
| 内存 | 16 GB | 32 GB |
| 磁盘 | 50 GB | 100 GB SSD |
| 网络 | 100 Mbps | 1 Gbps |

### 1.2 软件要求

- **Docker Desktop** 或 Docker Engine 20.10+
- **kind** v0.23+：`brew install kind` / `choco install kind`
- **kubectl** v1.30+：`az aks install-cli` / `brew install kubectl`
- **Helm** v3.10+
- **argocd CLI** v2.11+
- **cosign** v2.0+（可选，签名用）
- **PowerShell** 7+（Windows 用户）

### 1.3 快速验证

```powershell
docker version
kind version
kubectl version --client
helm version
argocd version --client
```

## 2. 一键部署

### 2.1 标准流程

```powershell
# 1. 创建多集群（约 5-10 分钟）
cd 03-implementation
.\kind\create-clusters.ps1

# 2. 部署 ArgoCD（约 3 分钟）
.\argocd\install-argocd.ps1

# 3. 部署 IAM（约 5 分钟）
helm install keycloak bitnami/keycloak --namespace keycloak --create-namespace `
  --values iam\keycloak\values.yaml
helm install dex dexidp/dex --namespace dex --create-namespace `
  --values iam\dex\values.yaml

# 4. 部署监控栈（约 10 分钟）
helm install kube-prometheus-stack prometheus-community/kube-prometheus-stack `
  --namespace monitoring --create-namespace `
  --values observability\prometheus\kube-prometheus-stack-values.yaml
helm install loki grafana/loki --namespace monitoring `
  --values observability\loki\values.yaml
helm install tempo grafana/tempo --namespace monitoring `
  --values observability\tempo\values.yaml
helm install mimir grafana/mimir-distributed --namespace monitoring `
  --values observability\mimir\values.yaml
kubectl apply -f observability\otel-collector\ -n monitoring
kubectl apply -f observability\prometheus\slo-rules.yaml -n monitoring

# 5. 部署 Harbor
helm install harbor harbor/harbor --namespace harbor --create-namespace `
  --values registry\harbor\values.yaml

# 6. 部署 Chaos + Velero
helm install chaos-mesh chaos-mesh/chaos-mesh --namespace chaos-mesh --create-namespace `
  --values chaos\chaos-mesh\values.yaml
helm install velero vmware-tanzu/velero --namespace velero --create-namespace `
  --values backup\velero\values.yaml
kubectl apply -f backup\velero\schedules.yaml -n velero

# 7. 部署 Kyverno（镜像签名准入）
.\registry\cosign\setup-cosign.ps1
kubectl apply -f registry\kyverno\

# 8. 部署 App of Apps
kubectl apply -f argocd\projects\
kubectl apply -f argocd\apps\

# 9. 部署示范应用
kubectl apply -f app\checkout-api\deploy\overlays\staging\ -n app-checkout-staging
```

### 2.2 一键全栈脚本

```bash
# Linux / macOS / WSL
bash scripts/deploy-all.sh
```

## 3. 访问入口

部署完成后，可用以下入口：

| 服务 | URL | 凭证 |
|---|---|---|
| ArgoCD | https://localhost:30443 | admin / kubectl get secret -n argocd argocd-initial-admin-secret |
| Grafana | http://localhost:30080 | admin / changeme |
| Prometheus | http://localhost:30080/prometheus | (via Grafana) |
| Keycloak | https://sso.ops.internal | admin / 启动日志中 |
| Harbor | https://harbor.ops.internal | admin / Harbor12345 |
| Chaos Mesh | http://chaos.ops.internal | - |

**注意**：kind 集群 Ingress 在本地通过端口转发（30080/30443）。生产环境用云厂商负载均衡器。

## 4. 日常运维

### 4.1 查看所有应用状态

```powershell
# ArgoCD 状态
kubectl --context ops-mgmt get applications -n argocd

# 集群 Pod 状态
for ($ctx in 'ops-mgmt','biz-prod-regiona','biz-prod-regionb') {
  Write-Host "=== $ctx ==="
  kubectl --context $ctx get pods -A
}
```

### 4.2 查看告警

```powershell
# 列出 firing 告警
kubectl --context ops-mgmt exec -n monitoring deploy/prometheus-operated -- `
  promtool query instant 'ALERTS{alertstate="firing"}'

# 或在 Grafana 的 Alerting 页面
```


```powershell

# 报告输出到 scripts/dr-drill/drill-reports/
```

## 6. 故障排查

### 6.1 ArgoCD 应用不同步

```bash
# 查看应用详情
argocd app get checkout-api-biz-prod-regiona

# 强制刷新
argocd app refresh checkout-api-biz-prod-regiona

# 硬重置
argocd app hard-refresh checkout-api-biz-prod-regiona
```

### 6.2 Prometheus 抓取失败

```bash
# 查看 targets
kubectl port-forward svc/prometheus-operated -n monitoring 9090
# 浏览器访问 http://localhost:9090/targets

# 检查 ServiceMonitor
kubectl --context biz-prod-regiona get servicemonitors -A
```

### 6.3 Keycloak 登录失败

```bash
# 查看 Keycloak 日志
kubectl --context ops-mgmt logs -n keycloak -l app.kubernetes.io/name=keycloak

# 检查 Dex 联邦
kubectl --context ops-mgmt logs -n dex -l app.kubernetes.io/name=dex

# 测试 OIDC discovery
curl https://dex.ops.internal/.well-known/openid-configuration
```

### 6.4 镜像签名失败

```bash
# 验证镜像签名
cosign verify --key registry/cosign/keys/cosign.pub harbor.ops.internal/app/checkout-api:v0.1.0

# 查看 Kyverno 拒绝原因
kubectl --context biz-prod-regiona get events -A | grep -i kyverno
```

### 6.5 跨集群网络不通

```bash
# 查看 Submariner 状态
kubectl --context ops-mgmt get clusters.submariner.io
kubectl --context ops-mgmt get endpoints.submariner.io

# 诊断
subctl diagnose all
```

## 7. 安全运维

### 7.1 镜像签名管理

```powershell
# 签署新镜像
cosign sign --key registry\cosign\keys\cosign.key `
  harbor.ops.internal/app/checkout-api:v1.0.0

# 验证签名
cosign verify --key registry\cosign\keys\cosign.pub `
  harbor.ops.internal/app/checkout-api:v1.0.0
```

### 7.2 Kyverno 策略管理

```bash
# 列出所有策略
kubectl --context ops-mgmt get cpol

# 测试策略（dry-run）
kubectl --context ops-mgmt get cpol disallow-privileged -o yaml | kyverno apply /dev/stdin --dry-run
```

### 7.3 凭证轮转

```bash
# 轮转 Dex client secret
kubectl --context ops-mgmt create secret generic dex-static-clients `
  --from-literal=static-clients.yaml=... -n dex --dry-run=client -o yaml | kubectl apply -f -
```

### 7.4 审计日志查询

```bash
# K8s 审计
kubectl --context ops-mgmt logs -n kube-system -l component=kube-apiserver | grep audit

# Keycloak 事件
kubectl --context ops-mgmt exec -n keycloak deploy/keycloak -- \
  /opt/bitnami/keycloak/bin/kcadm.sh get events --realm kubernetes
```

## 8. 进阶

### 8.1 添加新的业务集群

```powershell
# 1. 创建集群
kind create cluster --name biz-staging --config kind\clusters\biz-prod-regiona.yaml

# 2. 注册到 ArgoCD
kubectl config use-context ops-mgmt
argocd cluster add biz-staging --name biz-staging

# 3. 加 label
kubectl label cluster biz-staging env=staging

# 4. ApplicationSet 自动发现并部署
```

### 8.2 添加新的业务应用

```bash
# 1. 创建应用仓库
mkdir app/my-app
cd app/my-app
# 写 Dockerfile + Kustomize + 部署 YAML

# 2. 在 ArgoCD ApplicationSet 中添加（自动同步）
# 修改 argocd/apps/biz-cluster-apps.yaml 的 generators

# 3. 提交
git add . && git commit -m "feat: add my-app"
git push
```

### 8.3 自定义 SLO

```yaml
# 在 observability/prometheus/slo-rules.yaml 中添加
- alert: MyAppSLO
  expr: |
    (
      sum(rate(http_requests_total{job="my-app",status!~"5.."}[5m]))
      /
      sum(rate(http_requests_total{job="my-app"}[5m]))
    ) < (1 - (14.4 * 0.001))  # 99.9% SLO
  labels:
    severity: critical
    service: my-app
  annotations:
    summary: "my-app SLO burn rate critical"
    runbook: https://wiki.internal/runbooks/my-app
```
